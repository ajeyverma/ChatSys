# Contributing to ChatSys

Thank you for your interest in contributing to **ChatSys**.

ChatSys is a **fault-tolerant LAN communication system** designed to provide reliable messaging within local networks. Contributions help improve the stability, usability, and overall quality of the project.

Please read this guide before submitting contributions.

---

# Ways to Contribute

There are several ways you can contribute to ChatSys:

* Reporting bugs
* Suggesting new features
* Improving documentation
* Submitting code improvements
* Fixing issues

---

# Reporting Bugs

If you find a bug, please open an issue and include the following information:

* A clear and descriptive title
* Steps to reproduce the problem
* Expected behavior
* Actual behavior
* Screenshots or logs if applicable
* Your operating system and environment details

Before creating a new issue, please check existing issues to avoid duplicates.

---

# Feature Requests

We welcome suggestions for new features.

When submitting a feature request, please include:

* A clear explanation of the feature
* The problem it solves
* Possible implementation ideas (optional)

Feature requests may be discussed before being accepted for development.

---

# Development Setup

Follow these steps to set up the project locally.

## Clone the Repository

```
git clone https://github.com/yourusername/chatsys.git
cd chatsys
```

## Install Dependencies

```
npm install
```

## Run the Application

```
npm start
```

## Build the Application

```
npm run build:x64
```

---

# Branching Strategy

Please follow this branch naming format:

feature/feature-name
bugfix/bug-description
improvement/improvement-name
docs/documentation-update

Example:

```
feature/private-messaging
bugfix/server-timeout
docs/readme-update
```

---

# Coding Guidelines

To maintain code quality:

* Use clear and meaningful variable names
* Keep functions small and modular
* Comment complex logic
* Follow consistent indentation
* Avoid unnecessary dependencies
* Maintain existing project architecture

---

# Commit Message Guidelines

Write clear and descriptive commit messages.

Example:

```
Add distributed credential synchronization
Fix connection retry logic
Improve UI responsiveness
```

---

# Pull Request Process

1. Fork the repository.
2. Create a new branch for your change.
3. Make your modifications.
4. Test your changes locally.
5. Commit with a clear message.
6. Push the branch to your fork.
7. Open a Pull Request.

Your pull request should include:

* A description of the change
* Related issue number (if applicable)
* Screenshots for UI changes (if applicable)

Maintainers may request modifications before merging.

---

# Code Review

All contributions are reviewed before being merged.

Maintainers may:

* Suggest improvements
* Request changes
* Approve the contribution

Please respond to feedback respectfully.
